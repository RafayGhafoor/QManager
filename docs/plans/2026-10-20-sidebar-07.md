# Sidebar → shadcn sidebar-07 (icon-collapsing rail)

Branch `claude/sidebar-07-redesign-9e9435` (on `development-home`). Frontend only, no backend.

## What sidebar-07 adds that we don't have

Most of the shell already matches: group labels, Material rows, sub-menus in a `Collapsible`, `NavUser` footer, inset header with `SidebarTrigger` + vertical `Separator` + `Breadcrumb`. These are the gaps:

1. **`collapsible="icon"`**: today it's `offcanvas`, so collapsing hides the sidebar entirely.
2. **`SidebarRail`**: the thin edge strip you click to toggle. Not mounted today.
3. **Team-switcher header**: a dropdown with a logo tile, name, subtitle and an up/down chevron. Ours is an inline `Collapsible` that does nothing in icon mode.
4. **Sub-menu left rail**: a 1px vertical line beside the indented sub-items. U3.1 removed ours on purpose.
5. **Breadcrumb**: `hooks/use-breadcrumbs.ts` is a hard-coded English segment map that isn't translated and has drifted (it still lists `email-alerts`, `video-optimizer` and others). The template's crumb is "section > page".

## Icon-rail mechanics

- `SIDEBAR_WIDTH_ICON` goes from 3rem to **3.5rem**. Collapsed groups switch to `px-2`, so rows become **40px circles**. On a coarse pointer the wrapper sets `--sidebar-width-icon: 3.75rem` and rows get `pointer-coarse:size-11`, which meets the 44px floor.
- The pill indicator needs no change. It measures the active row, so in icon mode it becomes a circle under the active glyph, and the `ResizeObserver` tracks the width transition.
- Collapsed: sub-menus, chevrons, the Watchdog status label and group labels hide. The Watchdog row keeps its tonal fill, and its tooltip carries the status sentence. Tooltips use the existing `tooltip` prop (hidden when expanded or on mobile).
- `SidebarContent` keeps the hidden scrollbar and **scrolls in icon mode too**. shadcn's `overflow-hidden` would clip ~19 rows on a laptop, so I'll use `overflow-x-hidden overflow-y-auto`.
- Expanded touch targets: parent rows stay 42px (the deck spec). Sub-rows and the chevron get `pointer-coarse` 44px.

## Persistence

`SidebarProvider` writes the `sidebar_state` cookie but never reads it (static export has no server). I'll add a client read via `useSyncExternalStore`: the server snapshot is expanded and the client snapshot is the cookie. The gap/container width transitions are gated on a `data-ready` flag set after mount, so a reload never animates the collapse.

**Accepted residue:** on a hard reload, the pre-hydration static paint shows the sidebar expanded for a moment. Fixing that needs a pre-paint boot script plus CSS; I can do it as a follow-up if it bothers you.

## Switcher header (`app-switcher.tsx`)

It becomes a `DropdownMenu`, as in the template's `TeamSwitcher`:

- The trigger is the Q mark tile, then **QManager** with a subtitle of `APP_VERSION` (`lib/i18n/app-version`, already shown on About), then `unfold_more`.
- The menu opens on the right in icon mode and at the bottom on mobile. It has a label ("Apps"), **QManager** with a `check` glyph, and **LuCI** with the OpenWrt logo and `open_in_new` (new tab, as today).
- Glyphs are Material; all are already in the subset.

## Breadcrumb

`lib/nav-tree.ts` gets a pure `resolveNavCrumbs(pathname, groups)`. For the route it takes the **longest-prefix match** over the nav data and returns `[group?, parent?, page]`:

- `/cellular/settings/apn-management` → Cellular › Settings › APN Settings (parent is a link)
- `/system-settings/languages` → System › System Settings › Languages
- `/monitoring/watchdog` → Monitoring › Watchdog
- `/dashboard` → Home (a one-item group skips its own crumb)
- `/about-device` → About Device (the footer group has no label)

Group crumbs are plain text because groups have no URL. Labels come from the existing `sidebar` `groups.*` and `items.*` keys, so no new label strings are needed. Redirect stubs resolve by prefix: `/cellular/custom-profiles/connection-scenarios` → Custom Profiles. Unmatched routes show no crumb.

Below `desktop`, only the current page shows, as today. `hooks/use-breadcrumbs.ts` is deleted.

**Merge with `ss-regroup`.** That session edits only the contents of `navSystem` and `sidebar.json`. My changes in `app-sidebar.tsx`:

- export the four static arrays (`export` added to each `const` line, 4+ unchanged lines away from their edits)
- hoist `navMonitoring` to module scope, injecting Watchdog status at render by `t_key`
- export one `NAV_GROUPS` list, consumed by both the sidebar and the breadcrumb

No array contents change. Expected conflict: none, or at most a trivial one around the `navSystem` declaration line. `sidebar.json` gains a new `actions` and `switcher` key next to theirs, which should auto-merge unless both sides append at the same spot.

## Risks / rollback

- Icon mode on a shell tuned for 264px pills. Watch the pill indicator during the 800ms width transition and the 30px Q mark in a 40px slot.
- Hydration of the cookie state, mitigated by the server snapshot and the transition gate.
- Rollback is a revert of the branch; nothing here touches the backend or persistent device state.
